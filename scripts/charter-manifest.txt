# src/ 配下の各憲章ドキュメントについて、full 以外にどの配布ブランチへ含めるかを
# タグで指定する。
#
# - full ブランチは既定で [tags] に列挙された全ファイルを含み、[full-exclude] に
#   列挙したものだけを除外する。
# - full 以外の各ブランチ（lite・将来追加されるもの）は、そのブランチ名がタグと
#   して付いているファイルだけを含む（include 方式）。
# - src/scripts/ 配下のフックスクリプトは full にのみ自動的に含まれる（このファ
#   イルでの分類対象外）。
#
# 新しい配布ブランチ（例: python）を追加する場合：
#   1. 対象ファイルの行にタグを追記する
#   2. src/README-<branch>.md・src/README-<branch>-jp.md を作成する（任意）
#   3. .github/workflows/publish-charter-branches.yml の branch 一覧に追記する
# scripts/publish-branch.sh 自体の変更は不要。
#
# CHARTER_INDEX.md に列挙された全ファイルは、このファイルの [tags] に必ず1行
# 登録する（タグが無い行 = full 専用、で構わない）。未登録・削除漏れは
# scripts/check-charter-manifest.sh が pre-commit で検出する。
#
# full/lite 等で同じトピックの内容だけが異なる場合（例: branch protection の
# 必須項目の値がfull/liteで違う）は、別トピックの新規ファイルを作るのではなく
# <name>-<branch>.md という名前のファイルを追加する。publish-branch.sh が配布時
# にブランチサフィックスを除いた正規名（<name>.md）にリネームするため、各ブラ
# ンチには同じファイル名で内容だけ異なるものが配布される（README専用の
# src/README-<branch>.md リネーム処理を汎用化したもの）。CHARTER_INDEX.md 側は
# この生ファイル名（サフィックス付き）で行を登録する。full は既定で全ファイル
# を含むため、<name>-lite.md のような full 向けでない variant は必ず
# [full-exclude] にも追記すること（さもないと生ファイル名のまま full にも
# 混入する）。
#
# <name>-<branch>.md variant の登録漏れ（[full-exclude] 未登録、対応する基底
# ファイルの欠落、基底ファイルとの同一タグ重複）は scripts/check-variant-parity.sh
# が pre-commit で検出する。誤検出時のみ [variant-exceptions] にファイルパスを
# 追記して対象外にする（現時点で登録例なし）。
#
# format: <src/ からの相対パス><空白区切りのタグ（省略可）>
